>
> 如果你只有 20 分钟，请一定把这一章读完。它会告诉你：这门课到底有多深、每天该花多少时间、手机上能做什么不能做什么、卡住的时候该怎么办。

## 先说清楚：这门课是什么

你的目标很具体：**用 JS/TS + Node 开发网站和小程序**。

把这句话拆开，是四层能力，一层压一层：

| 层次 | 具体内容 | 学不好会怎样 |
| --- | --- | --- |
| 语言层 | 语法、数据类型、函数、作用域、异步 | 看得懂教程，写不出代码 |
| 浏览器层 | DOM、事件、网络请求、本地存储 | 做不出有交互的页面 |
| 工程层 | 模块化、npm、构建工具、Git | 项目一大就乱，无法上线 |
| 运行时层 | Node 接口、数据库、TypeScript、小程序 | 只能做静态页面，做不了全栈 |

这门课覆盖**前三层**，第 20 章给你第四层的完整路线图。

学完之后你应该能做到：

- 看到一段普通 JS 代码，能逐行说出它在干什么
- 独立写出一个「有界面、能请求接口、刷新不丢数据」的网页应用
- 看懂大多数前端项目里 70% 的代码，剩下的靠查文档补
- 知道下一步该学 TypeScript、Node 还是小程序，以及为什么

### 这门课不是什么

- **不是速成班**。20 章覆盖的是「能独立写项目」的地基，不是「三天上手框架」。
- **不是面试题合集**。面试题会在你真正理解之后自然能答，反过来背题没有用。
- **不会教你所有 API**。JS 有几百个内置方法，这门课只讲高频的、你必须形成肌肉记忆的那部分。剩下的查 [MDN](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript) 就行。

## 为什么通勤学习容易半途而废

先看清敌人，才好对付它。通勤学编程失败通常有三个原因：

**1. 把技术书当小说读**

每个字都认识，合上手机什么都写不出来。因为「读懂」只是识别，「写出来」才是回忆和组装，两者是完全不同的能力。

**2. 手机上试图敲代码**

手机输入 `{` `}` `(` `)` `;` 极其痛苦，一个分号能找半分钟。这种摩擦会迅速消耗掉你本就不多的学习热情，最后得出「我不适合编程」的错误结论。

**3. 追求「一次全懂」**

遇到一个没懂的点就停下来死磕，两小时过去还在第一页，进度停滞，然后放弃。

对应的三条对策，也是这门课的设计原则：

- 手机只负责**理解概念和判断对错**，代码在电脑上敲
- 每章末尾用**折叠自测题**检查「是否真懂」，而不是靠感觉
- 允许**带着问号往前走**，很多概念要学完后面几章才能回头看懂

## 每天两小时怎么分配

假设你单程通勤 1 小时。推荐这样切：

| 时间段 | 做什么 | 目标 |
| --- | --- | --- |
| 早上通勤 | 读新章节的前半部分 | 只求理解「为什么」，不求记住 |
| 午休 10 分钟 | 点开本章自测题，先自己想 | 找出没懂的点，标记下来 |
| 晚上通勤 | 读完剩下的部分 + 重看自测题 | 把白天不懂的地方补上 |
| 到家 30~40 分钟 | 在电脑上敲「动手练习」 | 跑通、改参数、看变化 |

一周下来，大约能扎实完成 2~3 章。20 章大约 8~10 周。这个速度不快，但它是**能坚持下来的速度**。

:::warn
不要给自己定「一周学完」的目标。编程不是背单词，理解需要时间沉淀。定得太急，你会在第 5 章左右放弃，然后过三个月重新从第 1 章开始——这是最常见的循环。
:::

## 一个完整的学习闭环

每章都按同一个循环走，养成习惯后效率会明显提升：

1. **读**：只看「为什么」。这段代码解决什么问题？不这样写会怎样？
2. **测**：点开「通勤自测」，遮住答案先自己想。想不出来是好事，说明找到了盲区。
3. **敲**：到电脑上把「动手练习」敲一遍。不要复制粘贴，手打。
4. **改**：跑通之后故意改坏它。把 `===` 改成 `==`、把 `let` 改成 `const`、删掉一个 `return`，看报什么错。
5. **记**：只记三句话——这章解决了什么、我踩了什么坑、我还没懂什么。

第 4 步最容易被跳过，但它才是真正让你记住的地方。看别人改错十次，不如自己制造一次错误。

## 手机上怎么读这套资料

这套资料做成了网页，可以装到手机主屏幕上，有这些能力：

- **自动记住进度**：每章读到哪、哪些标记为已读完，都存在你手机本地
- **继续阅读**：首页顶部有「继续阅读」，直接跳到上次的位置
- **可调字号**：右上角 `Aa` 按钮循环切换字号，通勤光线差时可以调大
- **可离线**：第一次完整打开后，内容会缓存到本地，地铁没信号也能读
- **本章目录**：小节较多的章节，正文上方有可折叠的目录

进度保存在**当前设备的浏览器**里。手机和平板各自独立，不会自动同步；需要迁移时用首页底部的「导出进度 / 导入进度」。

:::tip
读的时候不要追求「划重点」。技术内容不是历史书，划了也不会记住。真正有效的是每读完一节，在心里问一句：**如果让我给同事讲这一节，我会怎么说？** 说不出来，就回去再看一遍那几段。
:::

## 电脑上要准备的三样东西

全部免费，10 分钟能装完。

### 1. 浏览器控制台

Chrome 或 Edge，按 `F12`（Mac 是 `Option + Command + I`），切到 **Console** 面板。

这是你未来最常用的实验场。任何一行 JS 都能在这里立刻执行，不需要建文件、不需要保存、不需要运行：

```js
1 + 1
'hello' + ' ' + 'world'
[1, 2, 3].map(n => n * 2)
```

回车就会出结果。学这门课时，看到任何不确定的代码，都先粘到这里跑一下。

### 2. Node.js

去 [nodejs.org](https://nodejs.org) 下载 **LTS 版本**（长期支持版），一路下一步。装完打开终端（Windows 搜「PowerShell」）：

```bash
node -v
# 输出类似 v22.x.x 或 v24.x.x 就成功了

npm -v
# npm 是 Node 自带的包管理器，会一起装好
```

看到版本号就说明成功。这一步的意义是：**JS 不只能在浏览器里跑，也能在电脑上跑**。第 14 章之后你会经常用它。

### 3. VS Code

写代码的编辑器。装两个插件就够：

- **Chinese (Simplified) Language Pack**：中文界面
- **Prettier**：保存时自动格式化，省掉和空格、缩进较劲的时间

其他插件等真正需要时再装。一开始就折腾配置，是另一种拖延。

## 代码怎么看懂：三个提问法

初学者看代码容易「从左往右逐字读」，读完仍然不知道整体在干什么。改用一个更有效的方法：看任何一段代码，先回答三个问题。

**问题一：输入是什么，输出是什么？**

```js
function calcTotal(items) {
  return items.reduce((sum, item) => sum + item.price * item.count, 0);
}
```

先别管 `reduce` 怎么用。先问：传进去什么？传出来什么？答案是：传一个商品数组，返回总金额。知道这个，你就已经理解这段代码 80% 的用途了。

**问题二：如果删掉这一行，会发生什么？**

这能帮你判断每一行是「必需的」还是「可有可无的」。

**问题三：这段代码在什么情况下会出错？**

```js
function getFirst(arr) {
  return arr[0].name;   // arr 为空数组时会怎样？
}
```

养成这个习惯，你读代码的速度会明显快于逐字阅读，而且能提前发现 bug。

## 卡住了怎么办

一定会卡住，这很正常。按这个顺序处理：

1. **先跑一遍**。把代码粘到控制台，改几个值看输出。很多疑惑跑一次就没了。
2. **查 MDN**。搜索「MDN 方法名」，看函数签名、参数、返回值、示例。不要看二手博客。
3. **缩小问题**。把 20 行代码删到 5 行，只保留让你困惑的部分。大部分 bug 在缩小过程中自己就暴露了。
4. **允许跳过**。标记一个问号，继续往后读。第 9 章的闭包看不懂，可能第 13 章讲异步时回头一看就通了。
5. **别在同一个点上耗超过 40 分钟**。超过就记下来，第二天再看。疲劳状态下想不通的东西，睡一觉往往就通了。

:::warn
遇到报错不要慌，也不要立刻上网搜。先读报错信息本身：它通常明确告诉了你**哪个文件、哪一行、什么类型的问题**。第 17 章会专门教你读报错。现在只需要知道：报错是正常的，红色不代表你不行。
:::

## 20 章的地图

| 阶段 | 章节 | 你会得到什么 |
| --- | --- | --- |
| 语言基础 | 02~08 | 能读懂任何一段普通 JS 代码，能写出小工具 |
| 语言进阶 | 09~14 | 能理解框架源码里的奇怪写法，会用异步和模块 |
| 浏览器实战 | 15~18 | 能写出真正能用的网页应用 |
| 走向全栈 | 19~20 | 能建项目、能部署、知道下一步学什么 |

每一章的结构都是固定的：

- 开头一段说明「这章解决什么问题」
- 中间是概念 + 可运行代码 + 输出结果
- `提示` / `注意` 块补充易错点
- **通勤自测**：可折叠的问题，先自己想再点开
- **动手练习**：必做 3 题 + 进阶 2 题，每题有验收标准

## 学习节奏表

一份可以直接抄的周计划：

| 时间 | 任务 |
| --- | --- |
| 周一~周二通勤 | 读一章的前半部分，标记不懂的地方 |
| 周二晚 | 敲这一章的前两个练习 |
| 周三~周四通勤 | 读完这章，做一遍自测 |
| 周四晚 | 敲完剩余练习，改坏代码看报错 |
| 周五通勤 | 复习本周两章的自测题 |
| 周末 | 补齐没敲完的练习，或提前读下一章 |

如果某周特别忙，只完成「读 + 自测」也可以。**不要因为没敲代码就中断阅读**，保持连续性比单周进度重要得多。

## 常见误区清单

| 想法 | 实际情况 |
| --- | --- |
| 「我要先把语法全背下来再写项目」 | 语法是查出来的，不是背出来的。边写边查才是常态 |
| 「这个视频没看完不能看下一个」 | 视频看三遍不如自己敲一遍 |
| 「报错了说明我学得不好」 | 报错是主要的学习信号，专业开发者每天都在看报错 |
| 「收藏了就等于学会了」 | 收藏是拖延的伪装，只收藏你本周会看的 |
| 「我要搭一个完美的笔记系统」 | 手机备忘录三句话足够，工具折腾是逃避学习 |
| 「别人三个月能转行，我也可以」 | 别人的三个月可能是每天 6 小时，你的两小时要按比例算 |
| 「学完 JS 就能直接做小程序」 | 还需要框架、工具链和一遍完整的项目练习 |

## 通勤自测

:::quiz 如果今天只有 20 分钟，应该做什么？
读当前这一章的一小节，或者做本章的自测题。不要开新章，也不要试图在手机上敲代码。**保持连续性**比单次时长重要。
:::

:::quiz 为什么强调「晚上必须到电脑上敲一遍」？
因为「看懂」是识别，「写出来」是回忆加组装，两种能力完全不同。只有后者会形成长期记忆，也才是工作和面试真正考察的。而且敲的过程中会暴露你以为了解、其实误解的地方。
:::

:::quiz 读到第 9 章闭包完全不懂，应该停下来补，还是继续往后读？
先按「缩小问题」的方法试一次（把例子简化到 5 行跑一遍）。如果 40 分钟仍然不通，标记问号继续往后读。很多概念需要后面的知识才能反哺理解，卡死在一个点是通勤学习最常见的失败原因。
:::

:::quiz 这套资料的进度记录存在哪里？换手机会自动同步吗？
存在当前浏览器的 `localStorage` 里，只属于这台设备。换设备需要在首页用「导出进度」生成一份 JSON，再到新设备「导入进度」。没有服务器，所以不会自动同步。
:::

:::quiz 为什么手机只读、电脑才敲，而不是想办法在手机上写代码？
手机输入符号的成本极高，会消耗学习热情。手机适合「输入概念 + 判断对错」，电脑适合「输出代码 + 调试」。分工明确，两件事的效率都会更高。
:::

:::quiz 为什么把「通勤自测」做成可折叠的，而不是直接给答案？
折叠会迫使你先在心里输出答案，再点开对照。直接看答案容易产生「我懂了」的错觉；先想再验证，才能暴露真正的理解偏差。
:::

:::quiz 20 章全部读完大约要多久？某周只读没敲代码，算失败吗？
按每天通勤 2 小时、每周 2~3 章算，大约 8~10 周。某周只读没敲不算失败，保持连续性比单周产出更重要；但如果连续三周都没敲代码，就要停下来补练习，否则会退化成「读得懂、写不出」。
:::

## 动手练习（到电脑上做）

**必做**

1. 安装 Node.js，在终端执行 `node -v` 和 `npm -v`，把两个版本号记在备忘录里。
   验收：两条命令都能输出版本号，没有「不是内部或外部命令」的报错。

2. 打开浏览器控制台，依次执行 `1 + 1`、`'2' + 1`、`'2' - 1`、`typeof null`，把结果抄下来，并各自猜一个原因。
   验收：四个结果都拿到，且能说出 `'2' + 1` 和 `'2' - 1` 结果不同的原因（第 2 章会验证你的猜测）。

3. 在桌面新建 `hello.js`，写入 `console.log('我在学了')`，在文件所在目录执行 `node hello.js`。
   验收：终端输出「我在学了」。

**进阶**

4. 在控制台写一行代码，计算「一本书 59.9 元，买 3 本，打 8 折」的总价，要求输出保留两位小数。
   验收：输出 `143.76`（或你能解释为什么不是这个数）。

5. 用 `console.time` / `console.timeEnd` 包住一段循环，测出 `for (let i = 0; i < 1000000; i++) {}` 在你这台电脑上要跑多久。
   验收：能在控制台看到毫秒数，并知道这个数字只是参考、不同电脑不一样。

:::tip
做完第 3 题，你就已经跑通了「JS 不只在浏览器里运行」这件事——这正是 Node 存在的意义，也是你后面做接口开发的基础。

下一章正式开始。记住三件事：**默认用 `const`、一律用 `===`、字符串方法要接住返回值**。这三条会贯穿整门课。
:::
