运算符与表达式

从取余的真实用途讲到短路求值、空值合并与逻辑或的差别、优先级陷阱，把 JS 运算符一次讲清。

第 2 章你学会了给数据起名字，但变量只是「装东西的盒子」。真正让程序动起来的，是对盒子里的值做运算。

这一章讲运算符。加减乘除只是开头，真正卡住初学者的是三件事：% 到底什么时候有用、&& 和 || 为什么返回的不是布尔值、?? 和 || 该用哪个。

学完你应该能：看懂 const port = env.PORT ?? 3000 这类一行写法、推算出 x++ + ++x 的结果、并且在写条件时不再被隐式类型转换坑到。这些能力会直接用在第 4 章的分支判断里。

为什么需要它

假设你接了一个活动页：顶部要显示「距离结束还剩 2 分 05 秒」，列表奇数行加浅灰底，用户没填昵称就显示「匿名用户」。

你手里只有三个值：剩余秒数 125、行号 i、用户输入的昵称。把这三个值变成上面的效果，靠的全是运算符。

先看倒计时和奇偶判断：

// 1. 剩余 125 秒转成「几分几秒」
const seconds = 125;
const m = Math.floor(seconds / 60);
const s = seconds % 60;
console.log(m, s);   // 输出: 2 5

// 2. 判断奇偶
const i = 7;
console.log(i % 2 === 1);   // 输出: true

// 3. 没填昵称就用默认值
const nickname = '';
const displayName = nickname || '匿名用户';
console.log(displayName);   // 输出: 匿名用户

125 / 60 得到 2.0833…，Math.floor 砍掉小数拿到 2 分钟；125 % 60 拿到除不尽的 5 秒。你当然可以写 seconds - m * 60，但换成小时、分钟、秒三级换算时，% 的结构完全不用改。

第三段那一行确实比 if/else 短，但它只在「昵称不可能是 0、不可能是别的假值」时才等价。如果这个位置换成音量，用户设成 0 表示静音，|| 会把他的静音悄悄改成 50%。

所以这一章的重点不是背符号，而是搞清每个符号的前提条件。符号五分钟就能背完，用错一次可能要排查两小时。

还有一层原因：运算符决定了代码的「阅读顺序」。一段 a + b * c > d && e 摆在眼前，你能不能一眼看出先算什么，直接决定了排查问题时要不要反复翻文档。这也是本章最后要单独讲优先级的原因。

算术运算符

六个基本运算符，先跑一遍，再顺手把取整的方法也放进来对比：

console.log(7 + 2);    // 输出: 9
console.log(7 - 2);    // 输出: 5
console.log(7 * 2);    // 输出: 14
console.log(7 / 2);    // 输出: 3.5
console.log(7 % 2);    // 输出: 1
console.log(7 ** 2);   // 输出: 49

// 取整的几种方式
console.log(Math.floor(2.9));      // 输出: 2    向下取整
console.log(Math.ceil(2.1));       // 输出: 3    向上取整
console.log(Math.round(2.5));      // 输出: 3    四舍五入
console.log(Math.round(-2.5));     // 输出: -2   负数朝正无穷方向取
console.log(Math.trunc(-2.9));     // 输出: -2   直接砍掉小数
console.log((3.14159).toFixed(2)); // 输出: '3.14'

/ 和数学课本里的除法一样，JS 没有「整数除法」。7 / 2 就是 3.5，不会自动变成 3。这一点和 C、Java 不同，从别的语言转过来的人最容易想当然。

** 是幂运算，7 ** 2 是 7 的 2 次方。它从右往左结合，2 ** 3 ** 2 等于 2 ** 9，结果是 512，不是 8 ** 2 的 64。

最后一行再提醒一次：toFixed 返回的是字符串，因为它面向展示而不是继续计算。想再参与运算要 Number(...) 转回来。第 2 章提过这一点，这里又撞见一次，说明它真的很常出现。

Math.round(-2.5) 得 -2 也值得记一下：四舍五入在负数上不是「远离 0」，而是朝正无穷方向走。

% 的三个真实用途

很多人对 % 的印象停留在「数学课的余数」，其实它在代码里天天出现：

// 判奇偶
function isEven(n) {
  return n % 2 === 0;
}
console.log(isEven(4));    // 输出: true
console.log(isEven(7));    // 输出: false

// 把任意序号压回 0 ~ 2 的范围
const banners = ['A', 'B', 'C'];
console.log(banners[8 % banners.length]);   // 输出: C

// 余数的符号跟着被除数走
console.log(-7 % 3);       // 输出: -1

第二个用途就是轮播图的核心：不管用户点了第几次「下一张」，% 都能把序号折回数组长度以内，所以你不需要写「如果超过末尾就归零」的判断。分页也用它：第 n 条数据在第 Math.floor(n / 每页条数) 页，在页内是第 n % 每页条数 条。

第三个用途提醒你一个细节：余数的符号跟着被除数走。-7 % 3 是 -1，不是 2。做倒计时、分页这类只涉及正数的计算时不用担心，但如果要处理「把任意整数映射到 0 ~ 6」，就得先把它变成正数，这个技巧放在本章练习里。

时间换算：三个符号一起用

把 3725 秒转成 1:02:05：

const total = 3725;
const h = Math.floor(total / 3600);
const m = Math.floor((total % 3600) / 60);
const s = total % 60;

const text = h + ':' + String(m).padStart(2, '0') + ':' + String(s).padStart(2, '0');
console.log(text);   // 输出: 1:02:05

思路是「先取大单位，再把余下的部分交给下一级」：

单位算法结果
小时Math.floor(total / 3600)1
分钟Math.floor((total % 3600) / 60)2
秒total % 605

如果没有 %，分钟这一步要写 Math.floor((total - h * 3600) / 60)，多一个变量、多一处出错的机会。

padStart(2, '0') 是字符串方法，作用是把 '5' 补成 '05'。第 8 章会讲字符串的整套方法，现在照抄能用就行。

+ 的两种身份

+ 是唯一一个「看类型改变行为」的算术运算符：

console.log('2' + 2);       // 输出: '22'   字符串拼接
console.log(2 + '2');       // 输出: '22'
console.log(1 + 2 + '3');   // 输出: '33'   先算左边，3 再和 '3' 拼
console.log('1' + 2 + 3);   // 输出: '123'  先拼接，再继续拼
console.log('6' - '2');     // 输出: 4      减号强制转数字
console.log('6' * '2');     // 输出: 12
console.log('abc' * 2);     // 输出: NaN

1 + 2 + '3' 和 '1' + 2 + 3 的区别，是「从左往右依次计算」的直接结果。前者先算数字加法得 3，再遇到字符串变 '33'；后者第一步就变字符串，后面全在拼接。

-、*、/、%、** 都会把两边强制转成数字，转不了就是 NaN。所以从输入框拿到的值，做算术前一定要先转换，这一点第 2 章已经用 '10' + '20' 演示过。

自增与自减：前置和后置

++ 和 -- 只做一件事：把变量加 1 或减 1。但它们有两种写法，返回值不同。

写法名字执行顺序表达式的值
x++后置自增先返回，再加 1旧值
++x前置自增先加 1，再返回新值
let a = 5;
console.log(a++);   // 输出: 5，之后 a 变成 6
console.log(a);     // 输出: 6

let b = 5;
console.log(++b);   // 输出: 6，先加再返回
console.log(b);     // 输出: 6

// 后置自增的典型用法
const list = ['A', 'B', 'C'];
let index = 0;
console.log(list[index++]);   // 输出: A
console.log(list[index++]);   // 输出: B
console.log(index);           // 输出: 2

// 不建议：同一表达式里改两次同一个变量
let x = 5;
console.log(x++ + ++x);   // 输出: 12
console.log(x);           // 输出: 7

看不出来差别，是因为大部分时候你并不使用它们的返回值——for (let i = 0; i < 3; i++) 里没人关心 i++ 返回什么。

list[index++] 利用的正是「后置返回旧值」：先取 list[0]，再把 index 变成 1。这个技巧在旧代码里很常见，但今天更推荐写成两行：

console.log(list[index]);
index += 1;

最后那段 x++ + ++x 推一遍：左边的 x++ 取旧值 5，同时 x 变成 6；右边的 ++x 先把 6 加到 7，再返回 7；最后 5 + 7 = 12，x 停在 7。

结果虽然确定，但这种写法在真实项目里应该被禁止：它要求读代码的人在脑子里维护「此刻 x 是几」，而且换一门语言结果可能不同。日常规则很简单：**自增只用在 for 的第三段，其他场合写 i += 1**。

一元 + 与 -：最快的类型转换

在值前面放一个 +，会把它转成数字。它和 Number() 的行为完全一样，只是更短：

console.log(+'42');        // 输出: 42
console.log(+' 42 ');      // 输出: 42，前后空格被忽略
console.log(+'');          // 输出: 0
console.log(+true);        // 输出: 1
console.log(+null);        // 输出: 0
console.log(+undefined);   // 输出: NaN
console.log(+[]);          // 输出: 0
console.log(+[7]);         // 输出: 7
console.log(+[1, 2]);      // 输出: NaN
console.log(+{});          // 输出: NaN

// 常用场景：把用户输入或接口字符串转成数字
const raw = '12.5';
console.log(+raw * 2);     // 输出: 25

它比 parseInt 严格：parseInt('42px') 会从左往右读到 42 就停，而 +'42px' 直接是 NaN。两种行为都有用场——需要「尽量解析」时用 parseInt，需要「必须是完整数字」时用一元 +。

但有个必须警惕的地方：空字符串会被转成 0。

const input = '';
console.log(+input);              // 输出: 0
console.log(+input > 0);          // 输出: false

如果这个值代表「转账金额」，用户什么都没填，你拿到 0 元，后续校验很容易被绕过。所以转换前要先判断是不是空，写成 input.trim() === '' ? null : +input 才安全。

- 作为一元运算符只做「转数字再取负」，-'5' 是 -5，-'abc' 是 NaN，用得比 + 少。

比较运算符

大小比较返回布尔值，这部分看着最不会出错：

console.log(3 > 2);          // 输出: true
console.log('abc' < 'abd');  // 输出: true，逐字符比较
console.log('10' < '9');     // 输出: true，两边都是字符串
console.log(10 < 9);         // 输出: false，两边都是数字
console.log('A' < 'a');      // 输出: true，大写字母编码更小

console.log('10' > 9);       // 输出: true，字符串被转成数字
console.log('abc' > 9);      // 输出: false，NaN 参与比较永远 false

console.log(1 === '1');            // 输出: false
console.log(NaN === NaN);          // 输出: false
console.log(Object.is(NaN, NaN));  // 输出: true
console.log(Object.is(0, -0));     // 输出: false

关键在第三行：两边都是字符串时，按字符编码逐位比较，不按数值大小。'10' < '9' 先比第一个字符 '1' 和 '9'，'1' 的编码是 49，'9' 是 57，所以 '10' 更小。

这也解释了为什么排序一组字符串数字会得到奇怪的顺序：['10', '9', '100', '2'].sort() 的结果是 ['10', '100', '2', '9']，因为 sort() 默认把元素当字符串排。要按数值排必须传比较函数，第 6 章讲数组时会展开。

'abc' > 9 那一行更值得记住，它是排查 bug 时的噩梦：'abc' 转数字得到 NaN，而 NaN 和任何值比较都返回 false，包括它自己。所以如果页面上一堆「条件永远不成立」，先打印参与比较的两个值，看看是不是有一个成了 NaN。

规则：比较前先统一类型，Number(a) > b 永远比 a > b 清楚。

第 2 章已经讲过一律用 ===，这里补两个 === 也处理不了的角落。Object.is 只在两个场景下和 === 不同：它能判断 NaN 等于自己，也能区分 +0 和 -0。日常写业务几乎用不到，但读源码、写测试时会遇到。判断 NaN 更常用的还是 Number.isNaN(x)。

中文比较还有一个隐蔽的坑：字符串按 Unicode 码点比，不按拼音。'小明' < '小红' 是 true，因为「明」的码点比「红」小，但这跟拼音顺序毫无关系，换成「张三」和「李四」结果就可能反过来。要做中文排序必须用 localeCompare，第 8 章会讲。日常写业务时，除非在排英文文件名，否则别用 < 直接比较字符串。

逻辑运算符：短路与「返回操作数」

这是本章最重要的一节。先看六个结果：

console.log(1 && 2);            // 输出: 2
console.log(0 && 2);            // 输出: 0
console.log('小明' && '小红');   // 输出: 小红
console.log('' || '默认名');     // 输出: 默认名
console.log(0 || 100);          // 输出: 100
console.log(null || undefined); // 输出: undefined

const user = null;
console.log(user && user.name);  // 输出: null，右边没有执行

let calls = 0;
function track() {
  calls = calls + 1;
  return true;
}
false && track();
true || track();
console.log(calls);   // 输出: 0

console.log(!0, !'abc', !!'', !![]);
// 输出: true false false true

&& 和 || 返回的不是 true / false，而是其中一个操作数。规则只有两条：

  • A && B：A 是假值就返回 A，否则返回 B。
  • A || B：A 是真值就返回 A，否则返回 B。

也可以记成两句话：&& 找第一个假值，找不到就返回最后一个操作数；|| 找第一个真值，找不到就返回最后一个操作数。这两句话能覆盖所有组合，不用背真值表。

「短路（short-circuit）」的意思是：左边已经能决定结果，右边就根本不会执行。这不只是性能优化，而是可以拿来做条件保护：user && user.name 里，user 是 null 时右边的属性访问不会发生，否则会直接抛 TypeError。

后面那段计数器验证了短路：两次调用 track() 的机会都被短路掉了，所以 calls 还是 0。这个例子也说明：不要在有副作用的函数上依赖短路，读代码的人很容易以为它执行了。

! 是取反，!! 是把任意值转成布尔。哪些值是假值，第 2 章列过完整的 8 个：false、0、-0、0n、''、null、undefined、NaN。剩下的全是真值，包括 '0'、[]、{}——所以 !![] 是 true。

用 && 和 || 写默认值

在 ?? 出现之前，默认值几乎都是 || 写的：

function greet(name) {
  name = name || '匿名用户';
  return '你好，' + name;
}
console.log(greet());        // 输出: 你好，匿名用户
console.log(greet('小明'));  // 输出: 你好，小明

function setVolume(v) {
  return v || 0.5;
}
console.log(setVolume(0));   // 输出: 0.5

const isLogin = true;
isLogin && console.log('渲染用户信息');   // 输出: 渲染用户信息

第一段看起来没问题，因为「空名字」和「没名字」在这里确实可以当成一回事。但 setVolume 就出事了：用户把音量拖到 0 表示静音，函数却给了他 50% 的音量。类似的还有「折扣 0 折」「数量 0 件」「开关 false」，全都是合法数据，却会被 || 当成「没填」。

&& 的写法只在左边是真正的布尔值时可靠。如果左边是数字，0 && ... 会返回 0，3 && ... 会返回右边的东西，很容易在「本以为返回布尔」的地方拿到意外的值。

?? 空值合并：只认 null 和 undefined

?? 的规则比 || 窄得多：**只有左边是 null 或 undefined 时才用右边**。

console.log(0 || '默认');          // 输出: 默认
console.log(0 ?? '默认');          // 输出: 0
console.log('' || '默认');         // 输出: 默认
console.log('' ?? '默认');         // 输出: (空字符串)
console.log(false || '默认');      // 输出: 默认
console.log(false ?? '默认');      // 输出: false
console.log(NaN || '默认');        // 输出: 默认
console.log(NaN ?? '默认');        // 输出: NaN

const config = { retry: 0, label: '', debug: false };
console.log(config.retry ?? 3);        // 输出: 0
console.log(config.label ?? '未命名');  // 输出: (空字符串)
console.log(config.debug ?? true);     // 输出: false
console.log(config.timeout ?? 3000);   // 输出: 3000

对照着看，差别一目了然：

左边的值用逻辑或兜底用 ?? 兜底
0取右边保留 0
''取右边保留空串
false取右边保留 false
NaN取右边保留 NaN
null取右边取右边
undefined取右边取右边

配置对象是最典型的使用场景。retry: 0 表示「一次都不重试」，这是明确的业务决定，不能被默认值覆盖；timeout 没配，才该用 3000。label 是空字符串，也保留原样，因为「用户故意留空」和「字段不存在」是两种不同的状态。

赋值时也有对应的简写：

let a = null;
a ??= '默认';
console.log(a);   // 输出: 默认

let b = 0;
b ||= 5;
console.log(b);   // 输出: 5

// const x = a ?? b || c;   // SyntaxError: Unexpected token '||'
const x = (null ?? 1) || 2;
console.log(x);   // 输出: 1

??= 只在左边是 null / undefined 时赋值；||= 只要左边是假值就赋值，所以 b 从 0 变成了 5。这两个符号在初始化配置时很常见。

注意

?? 不能直接和 ||、&& 混用而不加括号，浏览器会直接报语法错误。这不是 JS 在刁难你，而是设计者担心 a ?? b || c 的意图有歧义，强制你加括号表态。遇到这类报错先看这一条。

选择规则可以压缩成三句话：

  1. 只有 null / undefined 算「没值」→ 用 ??。
  2. 0、''、false 也算「没值」→ 用 ||。
  3. 只需要判断「成立才做」→ 直接写 if，可读性比 && 好。

可选链 ?.：先认识一下

当对象可能只有两层、也可能有五层时，逐层判断会写成一堆 if。?. 可以在中间某一层是 null / undefined 时直接返回 undefined，不再往下读：

const user = { profile: { city: '上海' } };

console.log(user.profile.city);    // 输出: 上海
console.log(user.address?.city);   // 输出: undefined
console.log(user.address.city);    // 报错: TypeError: Cannot read properties of undefined

const list = null;
console.log(list?.[0]);            // 输出: undefined

const fn = null;
console.log(fn?.());               // 输出: undefined

const empty = '';
console.log(empty?.length);        // 输出: 0，空字符串不会被短路

const city = user.address?.city ?? '未知';
console.log(city);                 // 输出: 未知

它只对 null 和 undefined 生效，对 ''、0、false 不生效——empty?.length 就是证明。这一点和 ?? 的脾气一致，所以两个符号经常一起用。

注意

?. 不能救「变量根本没声明」的情况。notDefined?.name 依然会抛 ReferenceError: notDefined is not defined，变量本身要先声明。第 7 章讲对象时会展开嵌套读取、解构和可选链的完整用法。

也别滥用它。如果某个字段按接口约定一定存在，缺失就说明数据有问题，这时候让它痛快地报错反而更好排查；?. 只适合「这一层确实可能没有」的场景。

三元运算符

条件 ? 值1 : 值2 是 if/else 的表达式版本。区别在于：if 是语句，不能塞进赋值或模板字符串；三元是表达式，有返回值。

const score = 72;
const level = score >= 60 ? '及格' : '不及格';
console.log(level);   // 输出: 及格

const count = 0;
console.log(count > 0 ? count + ' 条' : '暂无数据');   // 输出: 暂无数据

// 嵌套三层，能跑但难读
const grade = score >= 90 ? 'A' : score >= 80 ? 'B' : score >= 60 ? 'C' : 'D';
console.log(grade);   // 输出: C

// 改成提前返回，一行一个条件
function toGrade(score) {
  if (score >= 90) return 'A';
  if (score >= 80) return 'B';
  if (score >= 60) return 'C';
  return 'D';
}
console.log(toGrade(85));   // 输出: B

三元适合的场景就是前两种：二选一赋值、二选一拼字符串。它不适合「做一件事」，只适合「产出一个值」。

另一条规矩：不要在三个位置里写赋值、console.log 或函数调用。flag ? save() : remove() 看起来很短，但读的人要先判断条件，再跳进两个函数，理解成本比写四行 if 高。三元里只放「取值表达式」，把动作留给 if。

嵌套三层就开始伤眼睛：结果是对的，但读的人要在脑子里做三次跳转。改写成提前返回的函数后，扫一眼就懂。这里用到了 return，第 5 章会系统讲函数，现在先记住结论：三元最多嵌套两层，再多就换成 if 或函数。

复合赋值

x += 1 是 x = x + 1 的简写，所有算术运算符都有对应形式：

let total = 100;
total += 20;   // 120
total -= 30;   // 90
total *= 2;    // 180
total /= 3;    // 60
total %= 7;    // 4
total **= 2;   // 16
console.log(total);   // 输出: 16

let n = 1;
n += '2';
console.log(n);       // 输出: '12'

let html = '<ul>';
html += '<li>苹果</li>';
html += '</ul>';
console.log(html);    // 输出: <ul><li>苹果</li></ul>

它不只是少打几个字。当左边是一个复杂表达式时，复合赋值只求值一次，例如 arr[i++] += 1 只会让 i 自增一次，而 arr[i++] = arr[i++] + 1 会自增两次。当然，这种写法本身就该拆开。

+= 用在字符串上同样是拼接，所以从输入框拿数字做累加前，记得先转换，否则 1 + '2' 会变成 '12'。第 2 章的隐式转换在这里会反复出现。

运算符优先级

完整的优先级表有二十多级，没必要背。下面这张只列你日常会遇到的，从高到低：

1   ()  []  .  ?.            调用、下标、属性访问
2   !  +  -  ++  --  typeof  一元运算
3   **                        幂
4   *  /  %                   乘、除、取余
5   +  -                      加、减
6   <  >  <=  >=              大小比较
7   ===  !==                  严格相等
8   逻辑与 &&                 两边都真才真
9   逻辑或 ||、空值合并 ??     兜底
10  ? :                       三元
11  =  +=  -=  ??=            赋值
12  ,                         逗号

记住两条就够用：

  1. 算术 > 比较 > 逻辑 > 赋值。所以 a + 1 > b && c 会先算 a + 1，再比较，最后才做逻辑判断。
  2. 不确定就加括号。括号不会让代码变差，看错优先级才会。

typeof 排在第 2 级，所以 typeof x === 'string' 会先算出类型字符串再比较，不需要写成 typeof (x === 'string')——后者是完全不同的意思，会把比较结果 true 交给 typeof，得到 'boolean'。

几个真实会踩的坑：

// 坑 1：赋值优先级最低，先算右边
let a;
a = null || '默认';
console.log(a);      // 输出: 默认

// 坑 2：条件里把比较写成了赋值
let isLogin = false;
if (isLogin = true) {
  console.log('永远进来');   // 输出: 永远进来
}

// 坑 3：一元负号不能直接接幂运算
// console.log(-2 ** 2);     // SyntaxError
console.log((-2) ** 2);      // 输出: 4

// 坑 4：幂运算从右往左
console.log(2 ** 3 ** 2);    // 输出: 512

第二个坑是新手最常犯的：if (isLogin = true) 把 false 改成了 true，赋值表达式的值又是 true，所以条件永远成立。现代编辑器会给出警告，但你不能依赖它，写条件时看到单个 = 就要警觉。

第三个坑很反直觉：-2 ** 2 不是「负二的平方」，而是语法错误。JS 规定一元运算符不能直接出现在 ** 左边，必须写 (-2) ** 2。写成 0 - 2 ** 2 才是「2 的平方取负」，结果是 -4。

a = b || c 本身没有错，错的是有人把它读成「a 等于 b 或者 c」。赋值永远最后执行，所以这行是「把 b || c 的结果赋给 a」，语义清晰。真正危险的是把这种读法带进条件：

const role = 'guest';
// 想表达：角色是 admin 或 editor
if (role === 'admin' || 'editor') {
  console.log('有权限');   // 输出: 有权限
}

'editor' 是非空字符串，永远是真值，所以这个条件永远成立。正确写法是 role === 'admin' || role === 'editor'，或者用数组 ['admin', 'editor'].includes(role)（第 6 章讲）。

位运算：一句话带过

&、|、^、~、<<、>>、>>> 直接操作二进制位：

console.log(5 & 3);     // 输出: 1    按位与
console.log(5 | 3);     // 输出: 7    按位或
console.log(5 ^ 3);     // 输出: 6    按位异或
console.log(~5);        // 输出: -6   按位取反
console.log(1 << 3);    // 输出: 8    左移 3 位
console.log(-8 >> 1);   // 输出: -4   带符号右移
console.log(8 >>> 1);   // 输出: 4    无符号右移

日常业务代码基本用不到，但读老代码时会遇到两个习惯写法：~~3.9 用两次取反把小数截成整数（结果是 3），x & 1 判断奇偶（x 是奇数时得 1）。看到了知道是什么意思即可，不建议在新代码里这么写。

通勤自测

下面两行分别输出什么？
console.log(2 + 3 * 4);
console.log((2 + 3) * 4);

第一行 14，先乘后加；第二行 20，括号优先。这条规则和数学课本一致。

这段代码输出什么？
let x = 5;
console.log(x++ + ++x);
console.log(x);

第一行 12，第二行 7。x++ 取旧值 5 后 x 变 6；++x 先加到 7 再返回 7；5 + 7 = 12。

下面四个表达式分别输出什么？
console.log('10' + 1);
console.log('10' - 1);
console.log(0 ?? 5);
console.log('' ?? 5);

'101'、9、0、''（空字符串）。前两个考 + 与 - 的区别，后两个考 ?? 只认 null 和 undefined。

用户把音量设为 0，代码 const v = input || 0.5 得到什么？该怎么改？

得到 0.5，静音被改成了半音量。改用 input ?? 0.5，只有没传值（null/undefined）时才用默认值。

console.log(1 && 0, 1 || 0, !0) 输出什么？

输出 0 1 true。逻辑运算符返回操作数本身而不是布尔值：1 && 0 返回 0，1 || 0 返回 1，!0 才是真正的布尔 true。

const name = nickname || '匿名' 在昵称为空字符串时返回什么？这算 bug 吗？

返回 '匿名'。昵称确实不该是空字符串，所以这里不算 bug；但如果换成「签名」「备注」这类允许为空的字段，用户主动清空后又被填上默认值，就是 bug，应改用 ??。

user?.profile?.city ?? '未知' 在哪些情况下返回 '未知'？

user 是 null/undefined、user.profile 是 null/undefined、city 本身是 null/undefined，这三种情况都会返回 '未知'。注意 city 是空字符串时不会兜底。

为什么 if (role === 'admin' || 'editor') 永远成立？

'editor' 是非空字符串，属于真值，所以逻辑或的右边直接作为结果，条件恒为真。应写成 role === 'admin' || role === 'editor'。

提示
