# 课程写作规范（内部使用，不发布）

本文件是扩写 `content/*.md` 的统一标准。所有章节必须严格遵守，保证 20 章风格一致。

## 读者画像

- 完全零基础，非科班，没写过任何编程语言
- 每天通勤 2 小时，用手机竖屏阅读，字号偏大
- 晚上能在电脑上敲代码，但不熟练，怕报错
- 最终目标：用 JS/TS + Node 做网站和小程序
- 已经读过旧版内容，反馈是「太简陋、对初学者不友好」

## 每章固定结构（顺序不可变）

1. **frontmatter**
   ```
   ---
   id: 03
   title: 运算符与表达式
   summary: 一句话说清这章讲什么、能解决什么问题（40~60 字）
   minutes: 30
   keywords: 空格分隔的关键词
   ---
   ```
2. **引言**：`> 三到五行`，说清「这一章解决什么问题、学完你能做什么、和前后章节什么关系」
3. **`## 为什么需要它`**：用生活化场景或一个真实的小问题引入，2~4 段。不要直接甩定义。
4. **知识点小节**（`##` / `###`），每节固定四拍：
   - 先给**最小可运行示例**（代码块）
   - 紧跟**运行结果**（单独代码块，用 `// 输出: ...` 或 `console.log` 注释表示）
   - 再解释**为什么这样写**、不这样写会怎样
   - 给**错误写法 vs 正确写法**的对比，或 `:::warn` 提醒
5. **`## 常见误区清单`**：表格三列 `写法 | 结果 | 为什么`
6. **`## 通勤自测`**：6~8 个 `:::quiz`，其中至少 3 个是「这段代码输出什么」的推演题
7. **`## 动手练习（到电脑上做）`**：必做 3 题 + 进阶 2 题，每题给**验收标准**（怎样算做对）
8. **结尾 `:::tip`**：点明这章与后续章节、真实项目的关联

## 长度与密度

- 正文 **4500~6500 汉字**（不含代码），代码块 **15~25 个**
- 每 300~500 字必须出现一次代码、表格或列表，避免大段纯文字
- 术语第一次出现必须给英文：作用域（scope）、闭包（closure）
- 宁可多举例、多对比，也不要堆名词解释

## 构建器支持的语法（只能用这些）

- 标题：`##` 到 `######`，**禁止 `#`**
- 列表：`-` 或 `1.`，嵌套用 2 空格缩进
- 代码块：三反引号 + 语言（`js` / `bash` / `text` / `json` / `html` / `css`）
- 表格：`| 列 | 列 |` + `| --- | --- |` 分隔行
- 提示块：`:::tip` 内容 `:::`；警告块：`:::warn`
- 折叠题：`:::quiz 问题` 换行写答案 换行 `:::`
- 行内：`` `code` ``、`**粗体**`、`*斜体*`、`~~删除线~~`、`[文字](https://url)`
- **禁止**：图片、`#` 一级标题、HTML 标签、任务列表 `- [ ]`、脚注、目录语法

## 文字风格

- 第二人称「你」，口吻像坐在旁边讲，不居高临下
- 允许口语，但不说「简单来说」「众所周知」「显而易见」这类空话
- 输出结果必须真实可推演，禁止编造
- 代码要能直接复制到浏览器控制台或 `node` 里跑
- 中文与英文/数字之间加空格：`用 let 声明`、`返回 42`
- 不使用 emoji

## 章节之间的衔接

- 引用前面章节的知识时写「第 2 章讲过」；预告后面写「第 9 章会展开」
- 同一概念在不同章节的深度要递增，不要重复讲一遍同样的例子
